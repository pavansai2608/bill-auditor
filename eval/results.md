### v2 - 2026-09-01

> **An earlier v2 row was withdrawn and re-run, not quietly deleted.** It
> reported **18 fabricated clauses** and **0.0 tool calls per bill**. Both were
> faults in the scorer, not in the system:
>
> - `evaluate.py` built its set of legitimate citations from `clauses.json`
>   alone, so the 18 lines that cited `IRDAI-List-I` - the citation the
>   non-payable fast path issues, and the one the answer key itself uses for
>   the same lines - were counted as inventions. v0 scored 0 only because v0
>   has no fast path. Fixed in `citable_ids()`, which now also loads
>   `non_payable.json`.
> - `_calls()` patched `core.audit` only, while the agent path calls
>   `core.agent`, so every retrieval and judge call on an `--agent` run went
>   uncounted.
>
> No verdict changed - only the scoring of it. `tests/test_eval_scoring.py`
> now pins both: a verdict citing `IRDAI-List-I` scores as valid, a made-up id
> still scores as fabricated, and calls through either module are counted. The
> fabricated-clause count is the project's central claim and it broke without
> anything failing, which is why it now has a test rather than a comment.
>
> The p95 below (62.2s) is a **cached** re-run. The same ten bills measured
> 267.1s p95 with a cold cache; treat the cached figure as a floor.

### v3 - 2026-09-01

> **A first v3 row was withdrawn and re-run.** It scored **50.0%**, below v2's
> 51.2%, and the cause was in the second pass rather than the scorer this time.
> `breach_ratio` took its ratio from any line whose per-day cap was breached.
> On B01 that was "ICU Charges 12,000 x 2 days" (ratio 0.4167) and on B04 a
> surgeon's fee (ratio 0.0526) - neither is room rent, and only a room rent
> breach triggers a proportionate deduction. The pass then cut every associated
> expense by a rule about a room the insured never breached, and did it with a
> correct-looking citation attached. Restricting the ratio source to room lines
> took B01 and B04 from wrong to exactly matching the key, and room_rent_over
> line accuracy from 36.0% (v2) to 60.0%.
>
> **Still open, and not a second-pass fault:** the `clean` category fell from
> 66.7% (v2) to 46.7%. On B05 the judge read the Star Health room limit as
> 800/day against a 4,000/day charge that is in fact within the 5,000/day
> entitlement, so it reported a breach that never happened. The second pass
> then correctly propagated a wrong premise to three more lines. That is the
> pass working as designed on a bad input, and it is the argument for the
> Phase 8 guardrail on room-rent limits: one wrong per-day figure is now worth
> four wrong lines instead of one.
